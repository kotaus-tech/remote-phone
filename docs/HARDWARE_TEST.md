# Проверка на целевом оборудовании

**Устройства:** OPPO Reno 15 · Android 16 · ColorOS 16; Windows 11 x64.
**Правило:** физические проверки отмечает пользователь. Зелёный CI не заменяет проверку на этих устройствах; незаполненное поле не считается пройденным.

## Этап 1 — стек и дизайн-макеты

Этап 1 согласован. Пользователь подтвердил установку APK и одобрил Android UI. Windows UI-багфиксы после масштабирования собраны; их отдельный ретест отложен пользователем до следующего крупного этапа и не блокирует текущий camera PoC.

## Этап 2 — ранний PoC виртуальной камеры Windows (текущий стоп-гейт)

**Цель:** проверить только установленную синтетическую камеру с движущимися полосами и шестизначным счётчиком. Это не камера телефона и не приёмка полной функции «Веб-камера».

**Аппаратный тест выполняется только свежим `Setup.exe` из зелёного CI и приложениями Windows.** Не скачивать отдельный native-архив, не запускать PowerShell-сценарии и не делать ручную COM-регистрацию. Установщик с повышением создаёт 64-разрядный CLSID в HKLM, ставит DLL в Program Files и готовит общий журнал в ProgramData; удаление снимает HKLM-регистрацию. Повышение требуется только установщику, приложение запускается обычно.

### Шаги на Windows 11 x64

1. Скачать `Видоискатель-Setup-0.1.0.exe` из последнего зелёного CI и установить. Если Windows запросит подтверждение администратора — это ожидаемое действие per-machine установщика.
2. Запустить «Видоискатель» и оставить приложение открытым. Тестовый host автоматически создаёт камеру; на странице **«Веб-камера»** дождаться состояния «Камера запущена».
3. Открыть `webcamtests.com`, выбрать **«Видоискатель — тестовая камера»** и проверить, что кадр меняется, а шестизначный счётчик заметно увеличивается. Если сайт предлагает режимы, записать фактически выбранные разрешение/частоту; его собственное значение FPS не считать измерением источника.
4. Закрыть браузер. Открыть OBS, добавить источник захвата видео, выбрать ту же камеру и проверить движение полос и счётчика.
5. Закрыть OBS. Открыть Discord, выбрать ту же камеру в предпросмотре и проверить, что предпросмотр и звонок работают, счётчик движется.
6. Закрыть веб-сайт, OBS и Discord, затем закрыть «Видоискатель». Камера является сеансовой и должна остановиться/исчезнуть из списков после обновления списка устройств. Удаление Setup.exe проверяет очистку HKLM-регистрации; журнал диагностики при удалении сохраняется.

**Журнал:** `%ProgramData%\Kotaus\RemotePhone\logs\VirtualCameraMediaSource.log`. Источник также пишет в `OutputDebugString`. Первая запись экземпляра источника содержит версию и SHA-256 реально загруженной DLL, PID, имя и путь процесса и путь DLL. В журнале далее должны быть `media_source_activate`, `selected_media_type`, `request_sample_cadence` и `stream_stopped` либо HRESULT ошибки. Частота запросов в журнале — измерение источника; цифра веб-сайта сама по себе ею не является.

**Объявленные режимы:** NV12 1280×720 и 1920×1080 при 30 и 60 fps; RGB32 640×480 при 30 fps оставлен для совместимости. Длительность образца рассчитывается по выбранной частоте (около 333333 × 100 нс при 30 fps и 166667 × 100 нс при 60 fps). CI должен перечислить режимы через Media Foundation и, если Windows runner поддерживает Frame Server, захватить несколько изменяющихся кадров 1080p60.

### Критерий прохождения

- [ ] В webcamtests.com виден меняющийся тестовый кадр и счётчик.
- [ ] В OBS виден тот же меняющийся кадр и счётчик.
- [ ] В Discord есть работающий предпросмотр/звонок и счётчик.
- [ ] После закрытия приложения тестовая камера остановлена; при удалении свежего Setup.exe постоянный CLSID удалён из HKLM64.
- [ ] Пользователь подтвердил прохождение всех трёх приложений. До такого подтверждения PoC считается **не пройденным**.

Если не пройдёт только Discord — диагностировать именно несовместимость Discord. В остальных случаях сохранить выбранный тип/разрешение/частоту, интервал `RequestSample`, HRESULT, первую запись ProgramData-журнала и результат каждого приложения; сообщить измерения и остановиться. Не начинать полную реализацию камеры до результата этого стоп-гейта.

## Этап 3 — локальное сопряжение и защищённый транспорт

Код локального сопряжения и защиты реализован; его аппаратная проверка остаётся отдельной от camera PoC. Пользователь попросил не делать отдельный ретест исправлений Android/Windows: проверить их вместе со следующим крупным этапом. Это разрешение не снимает camera PoC-гейт.

Реализованные ограничения сеанса: одноразовый 8-значный PIN, срок 5 минут, максимум 5 попыток, локальный IPv4, ограничение размера сообщения. Протокол OPAQUE и сетевой формат зафиксированы в [PAIRING_PROTOCOL.md](PAIRING_PROTOCOL.md); PIN не отправляется по сети и не должен попадать в журналы. Следующий защищённый медиатракт остаётся WebRTC DTLS-SRTP для видео и отдельный `RTCDataChannel` для команд; передача экрана/камеры и WebRTC пока не реализованы.

### OPPO Reno 15 / Android 16 / ColorOS 16

- [x] APK установлен; Android UI одобрен пользователем. Исправление закрытия приложения при ошибке JNI отложено до совместного теста со следующим крупным этапом.
- [ ] Установить свежий APK из зелёного CI; проверить оба режима и создание PIN. При сбое должно появиться русское сообщение; проверить Logcat и отсутствие PIN в сообщениях/журнале.
- [ ] Проверить автопоиск телефона и резервное подключение по локальному IP/порту, в том числе без доступа к интернету.
- [ ] Проверить правильный и неправильный PIN, лимит из пяти попыток, блокировку после лимита, истечение через пять минут и завершение сеанса. Переподключение/IP не должны сбрасывать лимит; PIN — только по явному действию на телефоне.
- [ ] Измерить время и пиковую память Argon2id на OPPO Reno 15; результат Linux CI не считать измерением телефона.

### Windows 11 x64

- [ ] С тем же свежим Setup проверить запуск приложения без повышения, обнаружение телефона и ручное подключение по IP/порту, включая сценарий без интернета.
- [ ] Проверить корректный/ошибочный PIN, пять попыток, истечение и очистку сеанса; убедиться, что PIN отсутствует в логах и захвате сетевого обмена.
- [ ] Проверить закрытие/повторный запуск и завершение локального discovery/порта. Проверку Windows UI-багфиксов совместить с этим этапом.
- [ ] При удалении Setup проверить очистку постоянной HKLM64-регистрации камеры.

## После успешного PoC

Сразу перейти к встраиванию камеры в приложение и подаче живого видеопотока с телефона; не откладывать отдельным промежуточным этапом. Риск GPU shared-texture остаётся обязательным собираемым тестом и стоп-гейтом до дальнейшей разработки видеотракта. Запись, аудио, ввод текста, USB/ADB, облако/аккаунты и обход защищённых окон не добавлять.
