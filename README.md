# Видоискатель

Личный проект для трансляции экрана и использования камеры телефона как веб-камеры Windows.

## Статус

- **Этап 1 согласован:** Electron + React/TypeScript для Windows; Kotlin + Jetpack Compose для Android; утверждены тёмная дизайн-система и список экранов.
- **Этап 2 — CI пройдена:** run [#37384956873](https://github.com/kotaus-tech/remote-phone/actions/runs/37384956873), commit `8cc4494` собрал Android APK, x64 native DLL/host и Windows `Setup.exe`; автоматическая установка/удаление и очистка COM-регистрации прошли на Windows runner.
- **Проверка на устройствах (со слов пользователя, 2026-10-06):** APK и Setup.exe установились; Android UI полностью одобрен. Исправлены растягивание предпросмотра на свободную область окна Windows и масштаб текста/кнопок. Отдельный повторный UI-тест не блокирует следующий этап по просьбе пользователя; см. CI [run #37387774007](https://github.com/kotaus-tech/remote-phone/actions/runs/37387774007), commit `c4c6169`.
- **Остаются отдельные аппаратные пункты:** работа синтетической камеры в приложениях Windows, её очистка после остановки/удаления и факт запроса прав администратора не подтверждены; отмечены в [чек-листе](docs/HARDWARE_TEST.md). Их не считаю пройденными.
- **Текущий блок — защищённое локальное сопряжение:** OPAQUE-ядро уже выдаёт временный PIN и выполняет проверку кода; добавлен общий код двоичных кадров, transcript рукопожатия, взаимных подтверждений и ChaCha20-Poly1305 для защищённой сигнализации. CI [run #37396199893](https://github.com/kotaus-tech/remote-phone/actions/runs/37396199893) проверил этот транспортный слой и собрал APK, Windows `Setup.exe` и нативные компоненты. Приложения пока не связаны с ядром: сокеты/WebSocket, поиск устройства и WebRTC ещё не реализованы. Живой поток телефона в виртуальную камеру — после готового транспорта и до основной разработки режима «Веб-камера»; критерии задержки и восстановления остаются обязательным стоп-гейтом.
