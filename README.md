# Видоискатель

Личный проект для трансляции экрана и использования камеры телефона как веб-камеры Windows.

## Статус

- **Этап 1 согласован:** Electron + React/TypeScript для Windows; Kotlin + Jetpack Compose для Android; утверждены тёмная дизайн-система и список экранов.
- **Сопряжение:** реализованы локальный OPAQUE/Rust-core, Android host/JNI, desktop-клиент, mDNS/DNS-SD и резервный ввод локального IP. Протокол и ограничения перебора описаны в [PAIRING_PROTOCOL.md](docs/PAIRING_PROTOCOL.md); аппаратный ретест Android/Windows-багфиксов пользователь попросил совместить со следующим крупным этапом.
- **Ранний PoC виртуальной камеры — не пройден:** прежний тест показывал изображение в браузере/OBS без нового счётчика, а Discord — пустой предпросмотр. Пользователь установил причину прежнего неудачного изолированного запуска: Frame Server не видел COM-регистрацию в HKCU; приложения могли загрузить старую DLL из Program Files. HKCU-диагностика прекращена.
- **Текущий путь PoC:** свежий per-machine Setup регистрирует CLSID в 64-разрядном HKLM, ставит DLL только в Program Files и настраивает ProgramData-журнал с ACL. Установленное приложение автоматически запускает и удерживает тестовую камеру. Требуемые режимы — NV12 1280×720 и 1920×1080 при 30/60 fps; кадр содержит движущийся фон и шестизначный счётчик. Аппаратная проверка — только через Setup и webcamtests.com, OBS и Discord; отдельных сценариев/нативных архивов для пользователя нет.
- **Приёмка:** PoC останется не пройденным до подтверждения пользователя, что движущийся кадр со счётчиком виден во всех трёх приложениях. Если не работает только Discord, диагностируется Discord. После прохождения сразу начинается встраивание камеры в приложение; риск GPU shared-texture — обязательный тест/стоп-гейт.
- **CI:** [последний зелёный запуск до изменений](https://github.com/kotaus-tech/remote-phone/actions/runs/37539412845) собрал исходную версию Setup. Текущие изменения установки, режимов и app-managed camera проходят обновлённые проверки; после зелёного результата здесь будет указан свежий run.
- **Граница реализации:** видео/аудио/управление по WebRTC пока не передаются. План защищённого транспорта — WebRTC DTLS-SRTP для медиа и отдельный `RTCDataChannel` для команд. Запись, аудио, ввод текста, USB/ADB, облако/аккаунты и обход защищённых окон вне области продукта.
