# Видоискатель

Личный проект для трансляции экрана и использования камеры телефона как веб-камеры Windows.

## Статус

- **Этап 1 согласован:** Electron + React/TypeScript для Windows; Kotlin + Jetpack Compose для Android; утверждены тёмная дизайн-система и список экранов.
- **Этап 2 — CI пройдена:** run [#37384956873](https://github.com/kotaus-tech/remote-phone/actions/runs/37384956873), commit `8cc4494` собрал Android APK, x64 native DLL/host и Windows `Setup.exe`; автоматическая установка/удаление и очистка COM-регистрации прошли на Windows runner.
- **Проверка на устройствах (со слов пользователя, 2026-10-06):** APK и Setup.exe установились; Android UI полностью одобрен. Исправлены растягивание предпросмотра на свободную область окна Windows и масштаб текста/кнопок. Отдельный повторный UI-тест не блокирует следующий этап по просьбе пользователя; см. CI [run #37387774007](https://github.com/kotaus-tech/remote-phone/actions/runs/37387774007), commit `c4c6169`.
- **Остаются отдельные аппаратные пункты:** работа синтетической камеры в приложениях Windows, очистка и активация COM-класса только для текущего пользователя службой обработки видеокадров Windows (Frame Server) не подтверждены; см. [чек-лист](docs/HARDWARE_TEST.md). Документация Microsoft указывает, что `MFCreateVirtualCamera(CurrentUser)` не требует администратора. Новый сценарий в архиве нативных компонентов Windows временно добавляет COM-запись только в HKCU, работает без повышения прав и удаляет запись; так проверяется, может ли системная служба открыть класс без регистрации в HKLM. Текущий Setup.exe не изменён: CI лишь упаковывает сценарий, подтверждение возможно только на целевой Windows 11.
- **Этап 3 — код локального сопряжения интегрирован:** Android host/JNI и desktop-клиент используют общий OPAQUE/Rust-core; добавлены mDNS/DNS-SD, WebSocket-рукопожатие и резервный ввод локального IP. CI [run #37477097263](https://github.com/kotaus-tech/remote-phone/actions/runs/37477097263), commit `bbe4cd2`, зелёный: собраны Android arm64 APK, Windows x64 native DLL и `Setup.exe`, автоматическая установка/удаление прошла. Это не означает, что сопряжение уже проверено на OPPO/Windows 11: обязательный аппаратный чек-лист остаётся в [docs/HARDWARE_TEST.md](docs/HARDWARE_TEST.md).
- **Отчёт пользователя (2026-10-06):** интерфейс в целом одобрен; найдено закрытие Android-приложения при создании PIN и переполнение заглушки камеры на Windows. Добавлены безопасная обработка ошибок JNI и адаптивное ограничение предпросмотра; CI [run #37485783285](https://github.com/kotaus-tech/remote-phone/actions/runs/37485783285), commit `3feeab6`, зелёный и проверяет упаковку обеих Android-библиотек сопряжения в APK. Пользователь отложил отдельный ретест этих исправлений до следующего крупного этапа. Страница настроек и переключатель управления остаются неактивными заглушками.
- **Ограничение этапа:** видео/аудио/управление не передаются; WebRTC DTLS-SRTP и отдельный `RTCDataChannel` не реализованы. Ранний PoC виртуальной камеры и проверка на целевом Windows 11 остаются обязательным стоп-гейтом до основной разработки режима «Веб-камера»; критерии задержки и восстановления обязательны.
